# 仕様とテストの矛盾

## 矛盾内容

テストファイル `tests/test_phone.py` の `test_tokyo` の期待値が仕様に矛盾しています。

### 仕様の要件（README.md）

> 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
> **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。

### 矛盾するテスト

```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

### 問題点

- 入力: `03-1234-5678` → 正規化後: `0312345678`（10桁）
- テストの期待値: `+810312345678` = `+81` + `0312345678`（先頭の `0` を削除していない）
- 仕様に従うべき値: `+81312345678` = `+81` + `312345678`（先頭の `0` を削除）

### 根拠

他のテストは仕様に従っています：
- `test_osaka`: `06-1234-5678` → `+81612345678`（先頭の `0` を削除）
- `test_yokohama`: `045-123-4567` → `+81451234567`（先頭の `0` を削除）

市外局番が異なる他の 10 桁のテストケースではすべて先頭の `0` を削除しており、東京の `03` だけが異なる扱いを受けるべき理由は、仕様にはありません。

### 修正の選択肢

1. テスト期待値を仕様に合わせる: `+81312345678` に修正
2. 仕様を修正: 市外局番 `03` の場合は先頭の `0` を削除しないと明記
