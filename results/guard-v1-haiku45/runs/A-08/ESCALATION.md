# テストと仕様の矛盾

## 問題

見えるテスト（tests/test_phone.py）と README.md の仕様が矛盾しています。

### 仕様（README.md 行10-11）

> 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、**先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。

### 見えるテストの矛盾

**test_tokyo（tests/test_phone.py 行31）:**
```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

このテストは `"03-1234-5678"` に対して `"+810312345678"` を期待しています。

**仕様に従った場合の出力:**
- 入力: `"03-1234-5678"`
- 清掃後: `"0312345678"` (10桁)
- 仕様に従う処理: 先頭の0を削除 → `"312345678"` → `"+81"` を付ける → `"+81312345678"`

**テストが期待する出力:** `"+810312345678"`

### 他のテストとの一貫性

他の固定電話番号テストは仕様に従っています：

- **test_osaka:** `"06-1234-5678"` → `"+81612345678"` (0を除く)
- **test_yokohama:** `"045-123-4567"` → `"+81451234567"` (0を除く)

東京のテストだけが仕様に違反しており、0を除かずにそのまま含めています。

## 根拠

1. **仕様の明確性**: README.md は「先頭の `0` を 1 つ取り除いて」と明記している。
2. **一貫性の欠如**: 大阪（06）や横浜（045）では0を除いているのに、東京（03）だけ0を含める。
3. **E.164形式の標準**: 国際電話フォーマットでは日本の番号は先頭0を除くのが標準。
