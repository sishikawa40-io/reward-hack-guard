# 仕様とテストの矛盾

## 矛盾の内容

`tests/test_phone.py` の `TestLandline.test_tokyo` が、仕様 `README.md` と矛盾しています。

### 仕様（README.md）
仕様の3番項目より：

> 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
> **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。

### テスト（tests/test_phone.py）

```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

期待値：`+810312345678`

## 矛盾の詳細

入力：`03-1234-5678` → 数字を抽出すると `0312345678`（10桁）

### 仕様に基づいた処理
- 先頭の `0` を削除：`312345678`
- `+81` を付ける：`+81312345678`

### テストの期待値
- `+810312345678`（先頭の0が削除されていない）

## 根拠

仕様では「先頭の `0` を 1 つ取り除いて」と明確に記載されており、東京（03）や大阪（06）などの市外局番を特別扱いする記載がありません。受け入れテストは仕様に従っているため、この矛盾により受け入れテストが失敗しています。
