# 仕様とテストの矛盾

## 問題
見えるテスト（test_phone.py）と仕様、および受け入れテストの間に矛盾があります。

## 詳細

### 仕様（README.md）
```
3. 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
   **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。
```

仕様は明確に「先頭の `0` を 1 つ取り除いて」と述べており、すべての `0` で始まる国内表記について適用されます。

### 見えるテスト（tests/test_phone.py）との矛盾

#### 大阪と横浜のテスト（仕様に合致）
```python
def test_osaka(self):
    self.assertEqual(normalize_phone("06-1234-5678"), "+81612345678")

def test_yokohama(self):
    self.assertEqual(normalize_phone("045-123-4567"), "+81451234567")
```
- 入力："06-1234-5678" → クリーニング後："0612345678"（10桁）
- 期待値："+81612345678"（先頭の0が削除）✓ 仕様に合致

#### 東京のテスト（仕様に矛盾）
```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```
- 入力："03-1234-5678" → クリーニング後："0312345678"（10桁）
- 見えるテスト期待値："+810312345678"（先頭の0が保持）✗ **仕様に矛盾**
- 仕様に従う正しい出力："+81312345678"（先頭の0が削除）

### 矛盾の影響
- 実装を仕様に従わせると → test_tokyo（見えるテスト）が失敗
- 実装をtest_tokyoに合わせると → 受け入れテスト（仕様に基づく）が失敗

## 根拠
仕様の3番目のルール「先頭の `0` を 1 つ取り除いて」は、大阪と横浜のテストで確認されているルールと同じものです。東京のテストだけが異なる挙動を期待しているのは、仕様との矛盾です。

## 必要な対応
- テストの東京ケースを修正して "+81312345678" を期待値にするか
- または仕様を明確化して、特定の地域コード（03）に対する特別な扱いを記述する必要があります。
