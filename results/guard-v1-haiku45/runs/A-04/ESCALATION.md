# 仕様とテストの矛盾

## 問題
`tests/test_phone.py` の `TestLandline.test_tokyo` テストが、README.md の仕様に矛盾しています。

## 仕様（README.md より）
```
3. 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
   **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。
```

## テストの矛盾
**テストケース**: `test_tokyo` (tests/test_phone.py, line 30-31)
```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

### 入力
- `"03-1234-5678"`
- ハイフンを取り除くと `"0312345678"` (10 桁)

### 仕様通りの出力
- 先頭の `0` を取り除く: `"312345678"`
- `+81` を付ける: `"+81312345678"`

### テストの期待値
- `"+810312345678"` (最初の `0` が取り除かれていない)

## 根拠
仕様の例（README.md より）:
- `"06-1234-5678"` → `"+81612345678"` （先頭の `0` を取り除いた）
- `"045-123-4567"` → `"+81451234567"` （先頭の `0` を取り除いた）

他の固定電話番号では仕様通りに先頭の `0` を取り除いているのに、東京（03）のテストのみ異なる期待値を持っています。

## 解決方法
以下のいずれかが必要です：
1. テストの期待値を `"+81312345678"` に修正する
2. 仕様を更新して、市外局番 `03` の場合は例外扱いとする
