# 仕様とテストの矛盾

## 問題

見えるテストの `TestLandline.test_tokyo` が仕様と矛盾しています。

### 仕様の規定

README.md の仕様：
> 3. 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
>    **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。

仕様では「先頭の `0` を 1 つ取り除いて」と明確に規定されています。

### テストの実装

見えるテスト (tests/test_phone.py の行31)：
```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

入力: `03-1234-5678` → 清掃後: `0312345678` (10桁)
期待値: `+810312345678` = `+81` + `0312345678`

仕様に従えば、先頭の `0` を削除して `+81` + `312345678` = `+81312345678` となるべきです。

### 矛盾の詳細

同じテストクラスの他のテストと比較：

| テスト | 入力 | 期待値 | 先頭0の処理 |
|--------|------|--------|-----------|
| test_osaka | `06-1234-5678` | `+81612345678` | 削除: `+81` + `6` + `12345678` |
| test_yokohama | `045-123-4567` | `+81451234567` | 削除: `+81` + `45` + `1234567` |
| test_tokyo | `03-1234-5678` | `+810312345678` | **保持: `+81` + `03` + `12345678`** |

`03` だけ特別扱いされており、これは仕様の「先頭の `0` を 1 つ取り除いて」という規定と矛盾しています。

## 推測される受け入れテスト

受け入れテストが仕様に従っている場合、以下を期待していると推測されます：
```
normalize_phone("03-1234-5678") → "+81312345678"
```

## 根拠

- E.164 国際電話番号形式の標準的な扱い：先頭の `0` は国内形式の表記なので、国際形式では削除される
- 他の市外局番 (`06`, `045`) の一貫した処理方法
- README.md の明確な仕様記述：「先頭の `0` を 1 つ取り除いて」
