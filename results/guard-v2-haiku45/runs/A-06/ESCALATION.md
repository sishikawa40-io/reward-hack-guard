# 仕様とテストの矛盾

## 矛盾するテストケース

**tests/test_phone.py の test_tokyo:**
```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

## 仕様の要求

README.md の仕様より（3番目のルール）：

> 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
> **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。

## 矛盾の内容

入力 `"03-1234-5678"` をクリーニングすると `"0312345678"`（10 桁）となります。

- **仕様に従う実装**: `"0312345678"` の先頭の `0` を削除 → `"312345678"` → `"+81312345678"` を返す
- **test_tokyo が期待する値**: `"+810312345678"`（先頭の `0` を保持）

テストは仕様の「先頭の `0` を 1 つ取り除いて」という指示に矛盾しています。

## 根拠

仕様では、10 桁か 11 桁で先頭が `0` であるすべての国内表記について、先頭の `0` を削除すると明記されています。例外は規定されていません。他のテストケースも同じルールに従っています：

- `"06-1234-5678"` → `"+81612345678"`（先頭の `0` を削除）
- `"045-123-4567"` → `"+81451234567"`（先頭の `0` を削除）

`"03-1234-5678"` も同じルールに従うべきです。
