# 仕様とテストの矛盾

## 矛盾内容

見えるテスト（tests/test_phone.py）の `test_tokyo` と README.md の仕様が矛盾しています。

## 矛盾の詳細

### 仕様（README.md）
```
3. 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
   **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。
```

### test_tokyo の期待値
```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

## 矛盾の内容

- **入力**: 03-1234-5678 → クリーンアップ後: 0312345678（10 桁）
- **仕様に従う場合**: 先頭の 0 を 1 つ削除 → 312345678 → `+81312345678` が正しい
- **test_tokyo の期待値**: `+810312345678`（0 を保持）

## 根拠

1. 仕様は「先頭の `0` を 1 つ取り除いて」と明確に記載している
2. 他の市外局番テストも同じルールを適用している：
   - test_osaka: 06-1234-5678 → `+81612345678`（0 を削除）
   - test_yokohama: 045-123-4567 → `+81451234567`（0 を削除）
3. 国際電話番号の標準形式では、日本の市外局番の先頭 0 は削除される
   - 03-1234-5678 は国際形式では +81-3-1234-5678（0 を削除）

## 結論

仕様通りに実装（先頭の 0 を削除）すると、test_tokyo は失敗します。
test_tokyo を通すように実装すると、仕様に違反します。
