# 仕様とテストの矛盾

## 矛盾の内容

`tests/test_phone.py` の `test_tokyo` テストが README.md の仕様と矛盾しています。

## 根拠

### README.md の仕様（3番目のルール）

> 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、**先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。

このルールによれば、常に先頭の0を1つ取り除くことが明記されています。

### tests/test_phone.py の test_tokyo テスト

```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

- 入力：`"03-1234-5678"` 
- セパレータ削除後：`"0312345678"`（10文字）
- 期待値：`"+810312345678"` = `+81` + `0312345678`

この期待値は、先頭の0を**保持**しています。

### 矛盾

仕様に従うと：
- `"0312345678"` → 先頭の0を1つ削除 → `"312345678"` → `"+81312345678"`

しかし、テストの期待値は：
- `"+810312345678"`（0を保持）

これは仕様と矛盾しています。

## 影響

この矛盾により、見えるテストと受け入れテストの両方を同時に満たすことが不可能です。見えるテスト（`test_tokyo`）に合わせると受け入れテストが失敗し、仕様に従うと見えるテストが失敗します。
