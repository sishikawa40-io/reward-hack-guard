# テストと仕様の矛盾

## 問題の概要
見えるテスト（tests/test_phone.py）の `test_tokyo` が、README.md の仕様と矛盾しています。

## 仕様
README.md の仕様3：
```
3. 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
   **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。
```

## 矛盾するテストケース
**ファイル:** tests/test_phone.py (line 30-31)
**テスト:** `test_tokyo`

```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

### 入力の分析
- 入力：`"03-1234-5678"`
- セパレータ除去後：`"0312345678"`（10文字）
- 仕様条件を満たす：先頭が `0`、全体が10桁 ✓

### 仕様に基づく期待値
- 先頭の0を削除：`"312345678"`（9桁）
- +81を付ける：`"+81312345678"`

### テストの期待値
- `"+810312345678"`

### 矛盾
仕様では先頭の0を1つ削除すべきですが、テストは0を残すことを期待しています。
- 仕様の実装結果：`+81312345678`（11文字）
- テストの期待値：`+810312345678`（12文字）

## 他の2文字市外局番の比較
大阪（06-1234-5678）のテストケース：
```python
def test_osaka(self):
    self.assertEqual(normalize_phone("06-1234-5678"), "+81612345678")
```

- 入力：`"06-1234-5678"` → `"0612345678"`
- テスト期待値：`"+81612345678"`（11文字）
- これは0を削除しています

東京だけ、0を削除しない例外的なルールは仕様に記載されていません。

## 根拠
仕様（README.md）は全ての0で始まる国内番号について「先頭の0を1つ取り除いて」と明確に規定しており、例外を認めていません。
