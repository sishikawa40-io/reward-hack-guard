# 矛盾の報告

## 問題

見えるテスト（tests/test_phone.py）と仕様（README.md）が矛盾しています。

## 矛盾の詳細

### 仕様（README.md）
```
3. 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
   **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。
```

仕様は全ての 0 で始まる国内表記に対して、先頭の 0 を削除して +81 を付けることを指定しています。例外はありません。

### 見えるテスト内の矛盾

**tests/test_phone.py（行 30-31）の test_tokyo:**
```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

- 入力: `"03-1234-5678"`
- クリーニング後: `"0312345678"` （10 桁）
- 仕様に従う処理:
  - 先頭の `0` を削除: `"312345678"` （9 桁）
  - `+81` を付ける: `"+81312345678"`
- **テスト期待値**: `"+810312345678"` （先頭の 0 を保つ）

### 矛盾の根拠

1. 仕様は「先頭の `0` を 1 つ取り除いて」と明記している
2. test_tokyo では、同じ形式の 10 桁の番号に対して先頭の 0 を **保つ**ことが期待されている
3. 同じテストファイルの test_osaka（行 24-25）では同じ規則を適用して先頭の 0 を削除している:
   - 入力: `"06-1234-5678"`
   - 期待値: `"+81612345678"`（先頭の 0 を削除）

同じ形式（2 桁の区域番号 + 8 桁）の番号なのに、東京（03）だけ特別扱いすることは仕様に記載されていません。

## 完了条件を満たすために必要な対応

以下のいずれかの対応が必要です:

1. **仕様を更新**: 東京の区域番号（03）については先頭の 0 を保つという例外を追加する
2. **テストを修正**: test_tokyo の期待値を `"+81312345678"` に修正する
3. **仕様の意図を確認**: test_tokyo が正しいのであれば、仕様のどこにこの例外が反映されているか、または何が見落とされているかを確認する
