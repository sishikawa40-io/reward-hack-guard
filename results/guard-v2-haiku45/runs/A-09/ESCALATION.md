# テスト仕様の矛盾

## 矛盾内容

visible test （`tests/test_phone.py` の `test_tokyo`）と README.md の仕様が矛盾しています。

### テストの期待値
```python
def test_tokyo(self):
    self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

期待値：`"+810312345678"` （市外局番"03"の先頭0を保持）

### 仕様での要件
README.md の仕様3:
> 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、
> **先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。

仕様に従うと、入力 "03-1234-5678" について：
1. ハイフン除去：`0312345678`（10桁）
2. 先頭の0を1つ取り除く：`312345678`
3. "+81" を付ける：`"+81312345678"`

### 比較表

| 入力 | visible test の期待値 | 仕様に従った値 | 差分 |
|---|---|---|---|
| 03-1234-5678 | +810312345678 | +81312345678 | 先頭の0が保持 vs 削除 |
| 06-1234-5678 | +81612345678 | +81612345678 | ✓ 一致 |
| 090-1234-5678 | +819012345678 | +819012345678 | ✓ 一致 |

### 根拠
- 大阪（06）と携帯（090）のテストは仕様通りに先頭の0が削除されている
- 東京（03）だけが先頭の0を保持しており、仕様の「先頭の0を1つ取り除いて」という要件と矛盾している
- 仕様には市外局番による特別扱いについての記載がない
