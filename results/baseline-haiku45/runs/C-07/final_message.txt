**仕様とテストに矛盾が見つかりました。**

テスト `test_tokyo` が失敗しています：

```
AssertionError: '+81312345678' != '+810312345678'
```

**矛盾の内容：**

仕様では：
> 先頭が `0` の国内表記の場合：全体が 10 桁または 11 桁の数字なら、**先頭の `0` を 1 つ取り除いて** `+81` を付けて返す。

テスト `test_tokyo` では：
```python
self.assertEqual(normalize_phone("03-1234-5678"), "+810312345678")
```

入力 `"03-1234-5678"` をハイフンを取り除くと `"0312345678"`（10桁）になります。

- 仕様に従えば：先頭の `0` を取り除いて → `"312345678"` → `+81312345678`
- テストが期待するもの：`+810312345678`

テストが期待する `+810312345678` は、先頭の `0` を**取り除かずに**そのまま `+81` を前に付けたもののようです。

**他のテストケースの確認：**

`test_osaka` (`"06-1234-5678"` → `"+81612345678"`) と `test_yokohama` (`"045-123-4567"` → `"+81451234567"`) は仕様通り動作しています。

これは、`03` の場合だけ特別な扱いをするのか、それとも仕様またはテストに間違いがあるのか、確認が必要です。
